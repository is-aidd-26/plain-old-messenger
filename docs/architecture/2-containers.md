# C4 — Уровень 2: контейнеры

Диаграмма раскрывает внутреннее устройство системы: отдельные модули и хранилище данных. Внешний контекст — на [диаграмме контекста](1-context.md).

```mermaid
C4Container
    title Plain Old Messenger — контейнеры

    Person(user, "Пользователь", "вход по никнейму")

    System_Boundary(pom, "Plain Old Messenger") {
        Container(spa, "Фронтенд", "", "SPA", "React + TypeScript")
        ContainerDb(db, "PostgreSQL", "", "диалоги и сообщения", "SQL")
        Container(api, "Бэкенд", "", "API-сервис", "C# + ASP.NET Core")
    }

    Rel(user, spa, "пишет и читает сообщения")
    Rel(spa, api, "REST/JSON")
    Rel(api, db, "читает и пишет")
```

## API бэкенда

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/dialogs` | список диалогов пользователя с идентификаторами |
| `POST /api/messages` | отправка сообщения `{from, to, text}`; находит или создаёт диалог и возвращает `dialogId` |
| `GET /api/dialogs/{dialogId}/messages` | история диалога; параметр `after` возвращает только новые сообщения (для поллинга) |

## Пояснения

- **SPA-фронтенд** исполняется в браузере пользователя (сам браузер показан на диаграмме контекста); новые сообщения получает опросом `GET /api/dialogs/{dialogId}/messages` раз в 2 секунды.
- **API** — единый процесс ASP.NET Core (Minimal API); сам данных не хранит.
- **PostgreSQL 18** — единственный процесс хранения: поднимается командой `docker compose up -d` и живёт в именованном томе, поэтому данные переживают перезапуски. Схема применяется мигратором при старте API; подробности — в [спецификации фичи](../specs/04-postgres.md).
- В dev-режиме SPA запускается через Vite Dev Server (:5173), который проксирует `/api` на API (:5000); на диаграмме это не показано, чтобы не привязываться к dev-инфраструктуре.
