# PRD — Plain Old Messenger

## 1. Обзор

Plain Old Messenger — предельно простой многопользовательский текстовый мессенджер.

Проект не является коммерческим продуктом: это каноничный пример (референс) для студентов курса.

Компоненты проекта:

- Бэкенд — API-сервис;
- Фронтенд — одностраничное веб-приложение.

## 2. Проблема и цели

**Проблема.** Студентам нужен эталонный проект, на котором видно, как выглядят простые, но качественные бэкенд и фронтенд, и как они стыкуются между собой.

**Цели:**

- Реализовать минималистичный мессенджер без особенностей: вход по никнейму, личные диалоги, отправка и чтение сообщений;
- Код должен быть образцовым: простым и надёжным;
- Документация должна быть актуальной.

**Нецелевые требования (out of scope):**

- Редактирование и удаление сообщений;
- Групповые чаты, каналы, чат-боты;
- Медиа: картинки, файлы, голосовые, эмодзи-реакции;
- Индикаторы «печатает…», «доставлено», «прочитано», статус «в сети»;
- Уведомления (push, email).

**Будет реализовано позднее**:
- Сохранение истории между перезапусками сервера;
- Регистрация, пароли, восстановление доступа;
- Масштабирование на много инстансов, высокая нагрузка, отказоустойчивость.

## 3. Целевая аудитория

- **Студенты курса** — читают код и используют проект как образец для собственных работ.
- **Преподаватели курса** — опытные бэкенд-разработчики; поддерживают проект и демонстрируют его на занятиях.

## 4. Пользовательские сценарии

1. **Вход.** Пользователь открывает приложение, вводит никнейм и попадает в мессенджер. Никакой регистрации нет.
2. **Начало диалога.** Пользователь видит список своих диалогов. Чтобы начать новый, он вводит никнейм собеседника.
3. **Переписка.** Пользователь открывает диалог, пишет текстовое сообщение и отправляет его. Сообщение появляется в переписке у обоих участников — с никнеймом автора и временем отправки.
4. **Чтение.** Пользователь открывает диалог и видит историю переписки, включая сообщения, пришедшие пока он был в другом диалоге.

## 5. Дизайн и UX

1. Стиль — подражание старым мессенджерам эпохи ICQ:
  - список контактов слева;
  - переписка справа;
  - лаконичные кнопки.
2. Цветовая схема — серая и блеклая: оттенки серого, отсутствие ярких акцентов. Проект намеренно не привлекает внимание дизайном.
3. Интерфейс на русском языке, лаконичные подписи, без иллюстраций и анимаций.

## 6. Критерии успеха

1. Проект без проблем запускается на компьютере студента.
2. Можно переписываться с самим собой в двух вкладках браузера. Можно переписываться двум людям с двух компьютеров.
3. Исходный код лаконичный и надёжный, в нём нет over-engineering.
