# Шаблон проекта на C# и React для студентов

Шаблон предназначен для курса «Технологии ИИ в разработке ПО» и состоит из двух частей:

* **Бэкенд** — простейший API на ASP.NET Core (.NET 10, C# 14) с единственным методом: приём сообщения чата. Сообщение никуда не сохраняется, только пишется в лог;
* **Фронтенд** — простейший SPA на React (форма отправки сообщения в чат), собранный утилитой Vite.

## Требования

* .NET 10 SDK: https://dotnet.microsoft.com/en-us/download/dotnet/10.0
* Node.js 20 или новее: https://nodejs.org/ (проверить версию: `node --version`)

## Система ASAP

Вы работаете со своим форком проекта, созданным системой [ASAP](https://asap.itmo.space/). [Документация ASAP](https://github.com/itmo-is-dev/asap-docs).

## Структура проекта

```
├── Chat.slnx                # Solution — файл «решения», в нём перечислены все проекты на C#
├── src/
│   └── ChatApi/             # Бэкенд: ASP.NET Core Minimal API
│       ├── ChatApi.csproj   # Файл описания проекта (компилируется в один DLL)
│       ├── Program.cs       # Точка входа: настройка API и его единственный метод
│       ├── ChatService.cs   # Сервис чата: приём сообщения и запись в лог
│       └── MessageRequest.cs# Описание тела запроса
└── frontend/                # Фронтенд: SPA на React + TypeScript, собирается Vite
    ├── index.html           # Единственная HTML-страница SPA
    ├── src/
    │   ├── main.tsx         # Точка входа React-приложения
    │   ├── App.tsx          # Форма отправки сообщения в чат
    │   └── App.css          # Стили приложения
    └── vite.config.ts       # Настройки Vite, включая прокси /api → бэкенд
```

Ликбез по типам файлов:

1. Файл `*.slnx` (Solution) — основной файл «решения» (то есть проекта), обычно один на репозиторий с кодом;
2. Файл `*.csproj` (C# Project) — файл с описанием одной Assembly (_рус._ Сборка), компилируется в один DLL, обычно используется как библиотека/модуль проекта;
3. Файл `package.json` — файл описания Node.js-проекта: список зависимостей и команд запуска.

## Запуск бэкенда

Бэкенд — обычное консольное приложение, запускаемое утилитой `dotnet` из .NET SDK:

```bash
# Сборка
dotnet build

# Запуск из корня репозитория, бэкенд будет доступен на http://localhost:5000
dotnet run --project src/ChatApi/
```

HTTP API имеет единственный метод — `POST /api/messages`. Он принимает JSON с полем `text` и пишет сообщение в лог (в консоль). Проверить можно утилитой `curl`:

```bash
curl -X POST http://localhost:5000/api/messages \
     -H "Content-Type: application/json" \
     -d '{"text": "Привет!"}'
```

В логе бэкенда появится строка `info: ChatApi.ChatService: Получено сообщение: Привет!`, а `curl` получит ответ `204 No Content`.

## Запуск фронтенда вместе с бэкендом

Понадобится две вкладки терминала.

Терминал 1 — запускаем бэкенд:

```bash
dotnet run --project src/ChatApi/
```

Терминал 2 — запускаем фронтенд:

```bash
cd frontend/
npm install   # однократно
npm run dev
```

Откройте в браузере http://localhost:5173 и отправьте сообщение. Оно появится в списке на странице, а в консоли бэкенда — в логе.

Как это работает: фронтенд отправляет запрос на относительный путь `/api/messages`, а dev-сервер Vite настроен проксировать такие запросы на бэкенд `http://localhost:5000` (см. файл `frontend/vite.config.ts`). Поэтому CORS не требуется, а фронтенд-код одинаково работает и локально, и в продакшене.

## Сборка и проверки

```bash
# Сборка бэкенда, в том числе статический анализ линтерами
dotnet build

# Переход в каталог фронтенда
cd frontend/

# Запуск линтера
npm run lint

# Автоформатирование
npm run format

# Сборка TypeScript в минимизированный JavaScript.
npm run build
```

## Статический анализ

Шаблон содержит подключённые статические анализаторы:

* Для C# анализаторы подключены в файле `Directory.Build.props` — система сборки MSBuild воспринимает этот файл как общие параметры сборки всего проекта;
* Для C# в корне проекта есть файл `.editorconfig` с настройками статических анализаторов;
* Для фронтенда настроены ESLint (файл `frontend/eslint.config.js`) и Prettier (файл `frontend/.prettierrc.json`).

Предупреждения анализаторов C# считаются ошибками сборки (см. `WarningsAsErrors` в `Directory.Build.props`).

Вы можете менять файлы настроек, подключать или убирать анализаторы — при условии, что это не снизит качество кода.

## Как был создан шаблон

```bash
# Бэкенд: создаём Solution и Minimal API
dotnet new sln -n Chat
dotnet new webapi -o src/ChatApi --use-minimal-apis
dotnet sln add src/ChatApi/

# Фронтенд: создаём SPA на React + TypeScript
npm create vite@latest frontend -- --template react-ts
```

Шаблон Vite дополнительно настраивался: убраны демонстрационные файлы, добавлены ESLint, Prettier и прокси `/api` на бэкенд в `vite.config.ts`.
