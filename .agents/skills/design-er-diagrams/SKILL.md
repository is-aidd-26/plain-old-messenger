# Проектирование ER-диаграмм

Здесь — правила моделирования схемы данных и создания ER-диаграмм.
Рендер, валидация и ловушки Mermaid — в скилле `design-mermaid-diagrams`.

## Порядок разработки

1. Сначала концептуальная схема — сущности и связи с кардинальностью, без атрибутов.
2. Затем логическая — таблицы с атрибутами, обобщёнными типами и ключами (PK/FK/UK), соединительные таблицы.
3. Перед каждым уровнем можно задать уточняющие вопросы.
4. После каждого уровня — пауза на ревью человеком.

Каждый уровень — отдельный markdown-файл в `docs/data/`.

## Тип диаграммы

Mermaid `erDiagram` — нотация «воронья лапка». Связь M:N на логическом
уровне отображается соединительной таблицей.

## Какие детали отсекать

- Концептуальный уровень — не показывать: атрибуты, типы и ключи
- Логический уровень — не показывать индексы
- Для всех уровней — не показывать особенности поведения кода, если диаграмма восстановлена по коду

Ограничения, которые нельзя выразить в рамках нотации, фиксировать текстом ниже диаграммы, а не на ней.
